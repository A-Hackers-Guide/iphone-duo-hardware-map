# Fact check, fourth pass

**Summary:** 30 claims re-derived from the primary evidence. None of them was checked in [FACTCHECK.md](FACTCHECK.md), [FACTCHECK-2.md](FACTCHECK-2.md) or [FACTCHECK-3.md](FACTCHECK-3.md). There are 12 claims from chapter 13, 12 from chapter 14, and 6 from the generated maps (`gpio-pins`, `syscfg-keys`, `driver-matches`, `coprocessors`, `function-codes`). For the maps, the generator in `tools/gen_*.py` was read and its output was recomputed independently. **24 CONFIRMED, 1 WRONG, 5 OVERSTATED, 0 UNVERIFIABLE.** None of the map errors is a misread byte: every decoded pin, phandle and code that was spot-checked matches the device tree. The problems are in headline counts and column labels. Checked 2026-10-30. No corrections have been applied yet.

Method notes:
- `duomap` means `python3 tools/duomap.py`. **DT** means `data/devicetree-exact.txt`. A small indentation-walking script resolved each matched line to its node path. **adt** means a short script over `data/adt-nodes.json` that decodes `function-*` words with `struct` (little-endian u32: phandle, code, args).
- **IPSW extract** means files unzipped from `iPhone19,4_27.2_24B91020_Restore.ipsw` into `scratchpad/factcheck4/`. Only `BuildManifest.plist` and `Firmware/embeddedaudioresources/image4/v68-boot-chime.im4p` were extracted, both well under 50 MB. The dyld cache was not touched.
- **Ramdisk catalog** means `reference/ramdisk/` (upgrade ramdisk 141-29011-104) and `reference/ramdisk-erase/` (erase ramdisk 141-28940-105). These pages list only the first 2,500 strings of each binary, so `restored_external` string claims beyond that window were not chosen for this pass.

## Other checks (all CONFIRMED, not counted)

- 14 §3: "PMGR has a direct line to it (`function-pmp_control`)". The property is on **`/arm-io/pmgr-child`** (`0x504d504300000077`, code `PMPC`), not on `/arm-io/pmgr`. pmgr-child is part of the PMGR block, so this is a precision note, not an error.
- 14 §3: `iop-smc-nub`, `iop-aop-nub`, `iop-pmp-nub` all carry `no-shutdown = 1`; `iop-aop2-nub` and `iop-sio-nub` carry `no-firmware-service`.
- 13 §2.4 row 4: `Cellular1,*` has 10 components in all three identities.
- 13 §2.4 caveat: `data/devicetree.txt` has 4 `canary` hits (the exact dump has 5 lines: the `gpio-canary` node's lines plus `/arm-io/sart-ans power-canary-offset`). That is consistent with "SoC and storage".
- 13 §1.4: `IgnoreSWDFailures`, `SkipJCOP`, `FillmoreBypassOTDataPersist`, `update_aht` are present in the first 2,500 strings of the erase-ramdisk `restored_external` catalog.
