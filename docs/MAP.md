# MAP: every hardware block of the iPhone Duo and the software that owns it

This is the master table of the map. Each row is one physical component or SoC block of the iPhone Duo (iPhone19,4, V68AP, SoC t8160, iOS 27.2 24B91020) that a chapter identifies. Each row follows the block from its device-tree node through its bus, firmware, kernel driver and secure path, up to the daemons, frameworks and public API that use it.

The table adds no new evidence. Every cell restates what a chapter (01–08, 10–12) or a generated reference page already establishes, and the **Chapter** column links to the section that has the evidence and the caveats. When the chapters disagree, the later userland chapter wins (for example, ProRes: [12 §3.1](12-userland-camera-ane-audio-security.md) corrects 04). Chapter 11 is still being written, so links into it may move.

## How to read this table

- **`?` means the chapters do not establish the cell.** It does not mean "nothing". **`none`** means a chapter shows there is nothing there: no node, no firmware image, or no driver.
- **Component** gives the part in bold and its codename in italics. Codenames are explained in the [Glossary](GLOSSARY.md).
- **Device-tree node(s)** link to the generated page for each node (`reference/devicetree/`). When the cell says `none`, the part is not described in the device tree; most often it sits behind a co-processor (AOP, SMC, the C2 modem) or is purely mechanical.
- **Bus / connection** is how the AP reaches the block: MMIO on the SoC fabric, an ASC/RTKit mailbox, SPMI, I²C, SPI, PCIe, or "AOP-private" when only the always-on processor talks to it.
- **Firmware image(s)** link to `reference/firmware/` when the image is its own file in the IPSW. Firmware that sits inside a larger container (an `ftab.bin` section, iBoot, or the exclave bundle) is named that way.
- **Kernel driver** is `IOClass (kext bundle)`, and the bundle links to `reference/kexts/`. A class bound to a node was checked with `python3 tools/duomap.py node`/`who`. A class that matches by PCI ID, HID usage or provider class (not by `compatible`) comes from the chapter and the kext page. N1 radio drivers are DriverKit dexts, which have no kext page.
- **Secure path** is `exclave` when the block has an exclave mailbox, proxy or exclave-only stream IDs. It is `SEP` when keys or matching live in the Secure Enclave. It is `none` when a chapter shows a plain AP path, and `?` when no chapter says.
- **Daemon(s) / frameworks** and **Public API** link to `reference/userland/` when a page exists. Names without a link are daemons outside the shared cache, or images with no page. "SPI" means private API.
- **Chapter** links to the most specific section. Several links mean the evidence is split across chapters.
- **Confidence** lists the evidence labels from [00](00-method-and-evidence.md) that support the row: **DT** device tree, **KC** kernelcache, **FW** firmware, **DSC** dyld shared cache, **RD** ramdisk, **PUB** public sources, **INF** inference. A row marked INF has at least one cell that is inferred; check the chapter before relying on it.
- Some blocks appear in two chapters. Each has one row here, placed in its main group, with both chapters linked. Generic plumbing that has a row of its own (DARTs, ASC wrappers, RTBuddy) also shows up inside other rows wherever a chapter names it as part of that block.
