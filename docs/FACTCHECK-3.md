# Fact check, third pass

**Summary:** 40 claims re-derived from the primary evidence. None of them was checked in [FACTCHECK.md](FACTCHECK.md) or [FACTCHECK-2.md](FACTCHECK-2.md). There are 23 claims from chapters 01, 04, 06 and 09, 12 rows of [MAP.md](MAP.md) and 5 rows of [GLOSSARY.md](GLOSSARY.md). **31 CONFIRMED, 6 WRONG, 3 OVERSTATED, 0 UNVERIFIABLE.** The most widespread error is in chapter 04: its register addresses are `/arm-io` child-bus addresses, not the CPU physical addresses used by chapter 01, MAP and `duomap addr`. Checked 2026-10-30. No corrections have been applied yet.

Method notes:
- `duomap` means `python3 tools/duomap.py`. **adt** means a short script over `data/adt-nodes.json` (the byte-exact device tree). It decodes `reg`, `interrupts` and other binary properties with `struct`, and counts properties and nodes directly.
- **Address translation.** `/arm-io ranges` was decoded as 10 entries of (child u64, parent u64, size u64). The first entry maps child `0x0`…`0x2_7fff_ffff` to CPU physical `0x2_0000_0000`. A node `reg` such as `0x81600000 0x1` is therefore child address `0x1_8160_0000` and CPU physical `0x3_8160_0000`. `duomap addr 0x381600000` returns `/arm-io/ispRtb`, and `duomap addr 0x181600000` returns nothing.
- **IPSW extract** means the file was unzipped from `iPhone19,4_27.2_24B91020_Restore.ipsw` into `scratchpad/factcheck3/` and unwrapped with `ipsw img4 im4p extract`, or read with `ipsw img4 im4p info`. The files were WirelessPower, Volchok `FirmwareMap.plist`, pmc, pmp, avd, msrf, Secure M3, AppleLPM, ansf/rans and both ANE images. The largest payload is 5.7 MB, and nothing over 50 MB was written. The dyld cache was not needed for this pass.
- **kexts** means every `IOKitPersonalities` entry in `data/kexts-full.json`, walked recursively. **classes** means `data/kernel-cpp-classes.txt`.
- **MAP rows.** Each node a row links to was checked with `duomap node` (direct driver binding, bus, `reg`, IRQ). Each claimed IOClass was then checked against the kext personalities.
